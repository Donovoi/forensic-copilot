# Bounded recovery from a filesystem catalog

`scripts/recover_catalog.py` exports NTFS DATA streams with The Sleuth Kit `icat` from an explicit JSONL catalog produced by the reviewed inventory helper. The runner and its imported gate module require independent script review before evidence use. This workflow covers cataloged streams; orphan streams, deleted-directory children absent from that catalog, unallocated blocks, slack, disk gaps, snapshots, and carving remain separate coverage work.

The default selects corroborated deleted type-128 (`$DATA`) attributes. `--all` also selects allocated DATA streams. Type-48 (`$FILE_NAME`), type-144 (`$INDEX_ROOT`), other metadata attributes, and directory records without an explicit DATA identifier remain inventory records. This includes TSK's virtual orphan directory; its cataloged DATA-stream children remain eligible. Bare file inodes without a complete attribute identifier are marked unsupported. Allocation flags that were inferred only from a filename suffix remain ambiguous and are deferred from extraction. Exact source rows and all path aliases are retained. Conflicting expected sizes on aliases stop that stream for review.

For targeted exports, `--select-streams SELECTION.json` selects exactly the full DATA identifiers listed in a strict UTF-8 JSON manifest. It is mutually exclusive with `--all` and can deliberately select both allocated and deleted DATA, including named alternate streams. No filename or path patterns are accepted. The manifest must contain exactly these three keys; replace the placeholder hash with the lowercase SHA256 of the selected catalog:

```json
{"schema_version":1,"catalog_sha256":"CATALOG_SHA256","stream_ids":["42-128-1","42-128-3"]}
```

The file must be at most one MiB, without a byte-order mark, and contain between one and 10,000 identifiers. Each identifier must have three decimal unsigned 64-bit components with no leading zeros. Duplicate keys, duplicate IDs, extra fields, bare record numbers, malformed IDs, and another catalog's hash are refused. Duplicate catalog references are different: all are retained and compatible aliases produce one export per full ID.

Selection validation streams the whole catalog while retaining only a small summary for each requested ID. Before opening the image or exporting any stream, it refuses the entire selection if an ID is missing, is not type-128 DATA, has an invalid matching catalog reference, has uncorroborated allocation flags, has a numerically equivalent but noncanonical identifier, or has aliases that disagree on size, deletion, or reallocation. An invalid selection reports `failed`; it never silently recovers a smaller subset. A fresh preflight failure creates no output/state roots. On a trusted resume, failure invalidates the previous success status under the existing state lock. Dry-run performs the same streaming selection validation without a database, image read, or output writes.

The selection file is a protected input: canonical path checks, a held Windows deny-write/delete handle, and hash/metadata rechecks apply. Its original bytes' SHA256, path, metadata, catalog hash, and sorted exact IDs are bound in `inputs.json`. Resume requires the same manifest bytes, path, metadata and normalized list; even whitespace or list-order changes are refused. A changed selection requires a separate fresh output/state pair. All catalog references and stream classifications remain in the recovery snapshots, including unselected problems; `selected_counts` and `recovered_all_selected` in selection mode describe only the explicitly requested IDs. `counts` and `invalid_catalog_rows` continue to expose the wider catalog's coverage gaps.

The catalog schema is version 1: `source_line`, `full_path`, `inode_attribute`, `mode`, `uid`, `gid`, `size`, `atime_epoch`, `mtime_epoch`, `ctime_epoch`, `crtime_epoch`, `deleted`, `reallocated`, `deletion_corroborated`, and `raw_line_sha256`. The full `record-type-id` attribute identifier is preserved. `full_path` stays exactly as recorded by TSK, including named streams and suffix annotations. Invalid identifiers, path traversal components, invalid sizes/times, and invalid allocation fields are recorded without invoking `icat` for those entries. Repeated source-line numbers and names remain distinct catalog references.

The catalog must remain inside the completed inventory directory with its original `manifest.json` and `status.json`. Before tool execution, the runner binds both inventory image identities to the current preservation gate, checks the exact image/output/preservation/tool paths and integer sector geometry, requires `catalog_bodyfile: true`, and requires the inventory producer script hash to equal the approved gate-module hash. The status must be complete and its recorded catalog path, SHA256, and byte count must match the selected catalog. This prevents a catalog from another image or partition from labeling recovered bytes. The catalog and both sidecars remain under read-only deny-write/delete handles throughout recovery on Windows; their hashes are recorded in recovery inputs and rechecked before completion and on resume. The entire inventory directory is a protected input root, so recovery state and exports cannot be placed inside it.

Pass explicit verified-image, preservation-state, preservation-exit-marker, TSK binary, catalog, output, and state paths. Output and state roots must be distinct and absent for a fresh run; their parents must already exist. All these paths and recovery manifests are controlled private case data and must stay in ignored staging locations. The script does not read the original image identified in the preservation manifest.

Symbolic-link and Windows junction aliases in those roots or their parents are refused through the pinned gate's path checks. The image parent is checked before preservation completes; the image itself is not stat'ed or resolved before its gate. Numbered image suffixes such as `.001` are refused because TSK may automatically read neighboring segments. The explicit sector offset must fall inside the verified image. Mutable state files, SQLite databases/journals/WAL/SHM files, and retained exports must be regular files with a single hard link. JSONL snapshots use randomly named exclusively created temporary files, and SQLite temporary storage stays in memory. These checks prevent preexisting aliases from redirecting state writes outside the controlled roots; the roots must remain under exclusive analyst control while running.

The inventory helper is loaded only from bytes matching `--gate-sha256`; pass the approved hash and module snapshot. Its gate requires successful preservation exit, verified status, equal full hashes, exact byte counts, and current destination identity/metadata. The runner holds a Windows read-only handle denying other writers/deletion through every `icat` subprocess, with metadata checks before and after each export. POSIX locks are advisory. Legacy preservation checks and their limitations are inherited from the reviewed gate. Runner, gate and tool hashes, tool version, catalog hash/metadata, partition offset in sectors, sector size, and selection mode are recorded in `inputs.json` and must match for resume. Use a frozen reviewed runner snapshot for long jobs; changing the runner requires an explicit reviewed migration or a separate output/state pair.

Example with placeholder paths and an examiner-supplied approved module hash:

```powershell
python scripts/recover_catalog.py --image 'C:\cases\CASE-001\image.raw' --preservation-state 'C:\cases\CASE-001\preservation' --preservation-exit-code 'C:\cases\CASE-001\copy.exit.txt' --tsk-bin 'C:\tooling\tsk\bin' --catalog 'C:\cases\CASE-001\inventory\bodyfile-catalog.jsonl' --output-dir 'C:\cases\CASE-001\recovered' --state-dir 'C:\cases\CASE-001\recovery-state' --gate-module 'C:\tooling\reviewed\collect_image_inventory.py' --gate-sha256 APPROVED_MODULE_SHA256 --partition-offset 63 --sector-size 512 --max-output-gib 128 --dry-run
```

Remove `--dry-run` only after review and the preservation gate. Dry-run validates preservation records, tools and catalog identity without opening the image or creating outputs. The required `--max-output-gib` caps cumulative retained export bytes, including old partial attempts; the default free-space reserve is 64 GiB. Reserve checks run before each stream and each write. If a stream does not fit, the job stops with `deferred`; raising the cap for an explicit resume can continue it. The cap covers export files, while catalog indexes, manifests, and bounded per-stream stderr use additional state space. Plan that separately. `--stream-timeout` defaults to 1,800 seconds per stream. Long streams may need a reviewed adjustment.

The runner calls `icat -i raw -f ntfs -b SECTOR_SIZE -o OFFSET [-r] IMAGE FULL_ATTRIBUTE_ID` through an argument list with `shell=False`. Deleted streams use `-r`. It never uses `-h`, which would remove sparse holes, or `-s`, which adds slack. Binary stdout is streamed under expected-size, total-byte and free-space checks; excess bytes are rejected before writing. Stderr is drained concurrently but retained only up to 64 KiB per attempt, with truncation and total-byte counts. Timed-out or interrupted children are stopped.

Every output has a numeric stream/attempt prefix plus a sanitized display name. TSK deletion annotations are removed from this display label; the full original name remains in the reference manifest. Original paths never determine output directories. Each attempt records command, stream ID, allocation flags, original display path, expected/actual sizes, process exit, error text, streaming SHA256, independently reread output SHA256/metadata, and UTC start/end. Completion requires exit 0, exact expected size, and matching independent hash. Empty streams receive the SHA256 of zero bytes.

Undecodable filename bytes retained by the inventory as Unicode surrogates are escaped only in SQLite display paths as visible code points such as `<U+DCFF>`, keeping SQLite TEXT valid and output labels safe. Ordinary Unicode is unchanged. The exact original `full_path`, including those surrogates, and `raw_line_sha256` remain in each JSON source reference; the protected catalog's bytes and hash remain authoritative. Display labels are not an encoding from which to reconstruct original names.

`recovery.sqlite3` is the durable working index. It links every catalog row and alias to a unique full attribute identifier and stores every export attempt. `source-references.jsonl`, `recovery-manifest.jsonl`, and `export-attempts.jsonl` are readable snapshots; `status.json` and `events.jsonl` describe current progress. The JSONL snapshots are refreshed at a clean stop or handled failure. After a hard crash, SQLite and the existing files may be newer than the last snapshots. Resume reconciles interrupted outputs and retains them explicitly.

Resume with the same paths and `--resume`. Skip occurs only for a completed prior output whose metadata and full SHA256 still match its recorded result, with exact input/tool/catalog/mode identity. Changed outputs and failed/partial attempts are retained, and a new numbered attempt is created. Unknown files in the output root, path escapes in the recorded manifest, and changed input identities are refused. A trusted resume invalidates the previous completion status under its state lock before gate/input checks. A different output/state pair is rejected without changing another case's record. Capture the invocation exit and stderr as well as status.

`complete` means the selected, supported catalog streams were exported with these checks. `complete_with_errors`, `deferred`, and `failed` are incomplete outcomes. No status claims that all deleted files on the filesystem were found. Successful deleted/reallocated extraction does not prove the old clusters were not reused, or that the exported content is authentic, internally consistent, or a decodable photo/video. Those require artifact and media validation.

