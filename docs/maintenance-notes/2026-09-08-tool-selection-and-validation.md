# 2026-09-08 - Tool selection and validation

## Problem and change

Named examples and optional implementation guides could be mistaken for a permanent tool stack. A tool's successful exit, a second interface to the same parser, or a catalog listing could also be mistaken for forensic validation.

The new selection policy and private-record template require capability-specific candidate comparisons, relevant version/configuration validation, explicit independent-check plans and disagreement handling. Root instructions, both agent prompt sets, the tooling matrix and report-review guidance carry the policy. Existing reviewed provider pins and execution contracts remain intact.

NIST CFTT methodology, the NIST tool catalog, SP 800-86 and IR 8354 were reviewed directly. The source addendum distinguishes their actual scope from the project's operational rules. It does not rank tools, certify the harness or claim that all functions require two commercial products.

## Review boundaries

This is a workflow and prompt update. It does not launch an examination, change native decoders, relax source protection, install a new toolchain, or migrate old case results to a new validation status. Completed selection records, validation outputs and case-specific paths remain private.
